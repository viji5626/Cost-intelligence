# 05 — Failure Mode & Architectural Bottleneck Analysis

## 1. Comprehensive Failure Mode & Effects Analysis (FMEA)

| Component | Failure Mode | Root Cause | Prob. | Impact | Detection Mechanism | Prevention Strategy | Mitigation & Safe Fallback | Recovery Action | Phase |
|---|---|---|---|---|---|---|---|---|---|
| **Data** | Invalid / Inconsistent Vehicle Hierarchy | Typo in model/variant codes in Excel upload. | High | Med | Schema validation & foreign key lookup tests during ingestion. | Pre-validated canonical dropdown mapping; quarantine unrecognized codes. | Flag row as `UNRESOLVED_HIERARCHY`; queue for admin mapping. | Admin updates synonym table; re-run ingestion. | Phase 2 |
| **Database** | Connection Pool Exhaustion | Unclosed sessions during parallel vector searches. | Med | High | PostgreSQL `pg_stat_activity` monitor; API 500 alert. | Async SQLAlchemy session context managers with strict timeouts. | Connection pooling with `max_overflow = 20` and pool recycle. | Auto-kill idle connections; restart pool. | Phase 0 |
| **Ingestion** | Partial / Corrupted Excel Upload | Network disconnect during file upload or corrupt file bytes. | Med | Med | File hash check and ZIP header validation before parsing. | Stream to temporary staging file; validate completely before database commit. | Reject upload with detailed user error; zero database mutation. | User re-uploads valid file. | Phase 2 |
| **OPEX** | Division by Zero in ₹/Vehicle | Zero or null production volume reported for plant in a period. | Med | Med | Deterministic pre-calculation check (`production_vol > 0`). | Guard clause in `CalculationEngine.opex`. | Return `N/A (Zero Production)` with descriptive tooltip. | User updates production record. | Phase 3 |
| **Ideathon** | False "New" Classification on Implemented Idea | Colloquial wording used in idea; part number missing. | Med | **CRIT** | Red-team test against known historical implementation benchmark. | Multi-tier retrieval (Part -> Assembly -> Subsystem -> Hybrid Search). | Assign `MEDIUM` confidence; require mandatory engineering review. | Engineer marks implementation; system updates synonym index. | Phase 7 |
| **Retrieval** | Vector Search Returns Irrelevant Candidates | Ambiguous query or semantic overlap with unrelated components. | Med | Med | Low cosine similarity scores (< 0.65). | Strict metadata filtering by vehicle subsystem before vector search. | Cross-encoder reranker filters out low-scoring candidates. | Broaden search scope or trigger exact keyword search. | Phase 5 |
| **Embeddings** | Embedding Service Timeout / Hang | Large batch of ideas processed synchronously on CPU. | Med | Med | 5-second request timeout; health check ping. | Batch chunking (max 32 texts per batch) with async worker queue. | Return cached embeddings or degrade to exact keyword search. | Worker auto-restarts and resumes batch queue. | Phase 5 |
| **Reranker** | OOM or High Latency on Large Candidate Set | Sending 100+ candidates to cross-encoder model. | Med | Med | Latency monitor (> 2 seconds). | Hard cap on reranker pool size (maximum top-25 candidates). | Truncate candidate list to top-15 before reranking. | Reset reranker batch size. | Phase 5 |
| **SLM** | Hallucinated Implementation Claim | LLM invents an ECN number not in provided context. | Med | **CRIT** | Regex extraction of cited ECNs matched against SQL database. | In-context evidence grounding prompt; temperature = 0.0. | Discard ungrounded claim; display `UNVERIFIED_CITATION` warning. | Human reviewer inspects primary records. | Phase 9 |
| **Local Runtime** | GGUF Model Loading Failure | Incompatible quantization or corrupted GGUF binary. | Low | High | SHA256 checksum and GGUF header verification on startup. | Model Registry validation script before activating model. | Fall back to CPU quantization (e.g. Q4_K_M) or safe fallback model. | Admin replaces corrupted model binary. | Phase 14 |
| **Tools** | Tool Parameter Schema Validation Error | SLM generates string instead of integer for part ID. | Med | Low | Pydantic v2 input validation exception. | Strict JSON schema / GBNF grammar definition passed to model. | Catch validation error, format error message, feed back to SLM for 1 retry. | Escalate to human if second attempt fails. | Phase 10 |
| **MCP** | External MCP Process Crash | Unhandled exception in optional external MCP server. | Med | Low | Process exit monitor; connection heartbeat. | Non-blocking async adapter with circuit breaker. | Isolate failure; continue core workflow using internal Python tools. | MCP client attempts background reconnect. | Phase 10 |
| **Frontend** | Table Freeze on 10,000 Ideas | Browser DOM overloaded by rendering 10,000 table rows. | High | Med | Lighthouse performance audit; browser memory check. | Virtualized lists (`tanstack-virtual`) and server-side pagination. | Render only visible viewport rows (max 50 DOM nodes). | Page remains responsive. | Phase 15 |
| **Backend** | Unhandled Exception in API Route | Uncaught edge case in business service. | Med | Med | Global FastAPI exception handler and Sentry/local log trace. | Comprehensive try-catch blocks in domain service boundary. | Return standard JSON error structure `{ "status": "error", "message": "..." }`. | Log trace for developer remediation. | Phase 0 |
| **GPU / VRAM** | CUDA Out-of-Memory During Inference | High context size (32k) exceeding 24GB VRAM. | Med | High | CUDA memory tracker (`torch.cuda.memory_allocated` / llama.cpp log). | Dynamic offloading: calculate VRAM budget per layer; limit context to 8k tokens. | Auto-spill excess layers to CPU RAM. | Restart inference engine with conservative layer count. | Phase 14 |
| **RAM** | Host System Memory Exhaustion | Multiple large Excel files parsed in memory concurrently. | Low | High | Docker container memory limits (cgroups). | Streaming chunked parsing with `calamine` / generator iterators. | Kill runaway ingestion worker; return 413 Payload Too Large. | Worker process resets cleanly. | Phase 2 |
| **Storage** | Disk Full from Uploaded Staging Files | Temporary upload directory not cleaned up after ingestion. | Med | Med | Disk space monitoring probe (> 85% full). | Automated post-commit file purge in `finally:` block. | Cron job deletes unverified staging files older than 2 hours. | Free up disk space automatically. | Phase 2 |
| **Security** | Unauthorized Access to Restricted Cost Data | Privilege escalation via forged JWT token. | Low | **CRIT** | JWT signature verification and role-permission matrix guards. | Cryptographically strong secret keys, short token expiry, HMAC-SHA256. | Immediate 403 Forbidden; log security event to audit trail. | Revoke user session. | Phase 0 |
| **Deployment** | Outbound Network Leak in Air-Gapped Mode | Library attempts external telemetry or update check. | Med | High | Network egress packet capture test. | Docker Compose `internal: true` network; block outbound TCP/UDP. | Packet dropped by firewall; zero data leaves boundary. | Audit logs confirmed clean. | Phase 16 |

## 2. Architectural Bottleneck Analysis

| Subsystem / Resource | Potential Bottleneck | Severity for POC | Solve in POC vs Defer | Mitigation Strategy |
|---|---|---|---|---|
| **Database (PostgreSQL)** | High connection churn on rapid search requests. | Low | **Solve Now** (Low Effort) | Use `SQLAlchemy` async connection pool (`pool_size=20, max_overflow=10`). |
| **Vector Indexing (pgvector)** | HNSW index build time on 50,000+ vectors. | Low | **Solve Now** | Build HNSW index with `m=16, ef_construction=64` after initial batch load. |
| **Embedding Generation** | CPU bottleneck if embedding 10,000 ideas sequentially. | Med | **Solve Now** | Batch inference (batch size = 32) using GPU or optimized ONNX/FastEmbed runtime. |
| **Cross-Encoder Reranking** | High latency (> 1.5s) if reranking > 50 candidates. | High | **Solve Now** | Hard cap reranker input to top-25 candidate records; sub-200ms latency on GPU. |
| **SLM Inference Latency** | Time-to-first-token on large 9B models. | Med | **Solve Now** | Use 4-bit / 5-bit GGUF quantization (Q4_K_M); pin 100% of model layers in GPU VRAM. |
| **Context Window Size** | Lost-in-the-middle accuracy degradation on > 16k tokens. | High | **Solve Now** | Context budgeting: Restrict prompt context to top-5 verified evidence chunks (< 2,500 tokens). |
| **Agentic Tool Execution** | Latency accumulation across multi-step tool calls. | Med | **Solve Now** | Limit max tool iterations to 4; execute independent tool queries in parallel (`asyncio.gather`). |
| **Excel File Parsing** | `openpyxl` high memory footprint on 100MB+ spreadsheets. | Med | **Solve Now** | Use Rust-backed `calamine` or streaming `openpyxl(read_only=True)`. |
| **GPU VRAM Contention** | SLM, Embedding, and Reranker competing for 24GB VRAM. | High | **Solve Now** | Sequential model loading or dedicated VRAM budget allocation: SLM (16GB), Embed (1GB), Reranker (2GB), KV Cache (4GB). |
| **Model Switching** | Swapping models in and out of GPU memory causes 5-10s latency. | Med | **Solve Now** | Keep SLM, embedding, and reranker concurrently resident in allocated VRAM partitions. |
| **Concurrent Users** | Multi-user contention on single local GPU during live demo. | Low (POC) | **Defer to Prod** | Queue user requests with FIFO concurrency lock (`asyncio.Semaphore(1)` for GPU generation). |
