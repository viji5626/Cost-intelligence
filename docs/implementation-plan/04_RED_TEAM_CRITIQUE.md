# 04 — Formal Red-Team Critique & Scenario Analysis

## 1. Executive Summary
This document conducts an aggressive red-team critique of Draft Implementation Plan V1 across all architectural, operational, and AI dimensions. It attacks fragile assumptions, single points of failure, edge cases, and hallucinations to stress-test the system before finalizing Revised Plan V2.

---

## 2. 32 Mandatory AI & System Red-Team Scenarios

| # | Scenario Description | Vulnerability / Failure Mechanism | System Protection & Architecture Defense |
|---|---|---|---|
| 1 | **Differently worded ideas mean the same thing** (e.g. "lightweight battery bracket" vs "reduce mass of accumulator holder"). | Vector distance might be moderate; exact keyword matching fails completely. | **Semantic Embedding + Cross-Encoder Reranker + Canonical Entity Extraction**. Ideas are mapped to the same subsystem/component entity in SQL before semantic clustering. |
| 2 | **Similar-looking ideas are technically different** (e.g. "change rear sprocket teeth for fuel economy" vs "lightweight rear sprocket material"). | High naive embedding similarity could trigger a false duplicate merge. | **Structured Entity & Mechanism Matching**. System compares both target component AND modification mechanism (Geometry vs Material vs Software). If mechanisms diverge, ideas are tagged as related but distinct. |
| 3 | **Existing implementation uses completely different terminology** (e.g. historical project named "Project Falcon Mass Optimization"). | Keyword search fails; semantic similarity to vague project name is low. | **Multi-tier Linkage via Part Numbers & Assembly Hierarchy**. The implementation search traverses Part -> Assembly -> Project ECN, bypassing colloquial project title matching. |
| 4 | **Implementation exists only on one variant** (e.g. Splendor Plus Disc vs Splendor Plus Drum). | Binary "already implemented" flag would erroneously dismiss an opportunity for standard drum variants. | **Variant-Specific Applicability Matrix**. Implementation records are bound to specific `variant_id` and `model_year`. System explicitly reports: "Implemented on Disc; Open Opportunity on Drum". |
| 5 | **Implementation exists on another model** (e.g. implemented on Glamour, suggested for HF Deluxe). | Searching only HF Deluxe records would miss the existing engineering solution. | **Cross-Model Component Sharing Traversal**. System searches the global component master to find shared parts implemented across sibling product families. |
| 6 | **Implementation is historical but not current** (e.g. implemented in 2021, discontinued in 2023 due to supplier issues). | Marking as "Currently Implemented" blocks a valid re-introduction idea. | **Temporal Validity Checks (`valid_from`, `valid_to`, `is_active`)**. Historical implementations without active BOM presence are tagged as `HISTORICAL_REFERENCE` with a flag to review discontinuation reasons. |
| 7 | **Relevant implementation record is not retrieved**. | Missed implementation creates false "new" decision, wasting engineering effort. | **Hybrid Search with Trigram Fuzzy Matching + Hierarchy Rollup**. Traverses up to Subsystem and Assembly levels if direct Part lookup yields zero matches. |
| 8 | **Vector search retrieves the wrong component** (e.g. Brake Lever instead of Clutch Lever due to semantic closeness). | Both are handlebar-mounted aluminum levers. | **Strict Relational Subsystem Filtering**. Vector search is constrained by extracted/confirmed `subsystem_id` (Brakes vs Transmission). |
| 9 | **Exact part number is missed by semantic search**. | Vector embeddings compress token details, losing precise alphanumeric strings. | **Dual-Stream Retrieval (Exact Stream + Semantic Stream)**. Exact part numbers are matched directly via PostgreSQL B-Tree / Trigram indexes and prioritized with maximum weight. |
| 10 | **Conflicting implementation records exist** (e.g. Project says complete, BOM shows old part). | System could make a false automated determination. | **Conflict Detection Engine**. Flags discrepancy, assigns `LOW/CONFLICT` confidence, and forces escalation to the Human Review Queue with side-by-side evidence diff. |
| 11 | **BOM cost is missing in structured database**. | Calculation engine fails or divides by zero. | **Explicit `MISSING_BOM_COST` Flag**. System displays unquantified status; LLM is strictly prohibited from guessing or fabricating cost data. |
| 12 | **Proposed cost saving is missing in idea submission**. | Financial ranking cannot be calculated. | **Historical Benchmark Cost Estimation (Clearly Labeled)**. System estimates potential range based on historical comparable part modifications, marked as `ESTIMATED_BENCHMARK`, requiring human cost engineer sign-off. |
| 13 | **Model invents / hallucinates a cost saving**. | Serious financial risk to business case validity. | **Deterministic Tool Calculation Guarantee**. Cost fields in API response are generated exclusively by the Python `CalculationEngine`. Model output is discarded if it diverges from calculation service output. |
| 14 | **Model invents / hallucinates implementation evidence**. | Engineers waste time chasing non-existent ECNs. | **Source Citation Validator**. Every cited ECN/Project ID is validated against PostgreSQL primary keys before rendering to the user. Unmatched citations are stripped and flagged. |
| 15 | **Context window becomes too large (> 32k tokens)**. | Slow inference, high VRAM consumption, increased error rate. | **Strict Context Budgeting & Token Truncation**. Reranker selects only the top-5 most relevant chunks; tabular data is formatted into compact Markdown summaries (< 2,000 tokens total). |
| 16 | **Relevant information is buried in context (Lost-in-the-Middle)**. | Model overlooks the critical ECN buried in middle paragraphs. | **Primacy / Recency Context Structuring**. Key constraints and candidate implementation facts are placed at the very top and very bottom of the prompt template. |
| 17 | **Embedding model changes / updates**. | Existing vector indexes become incompatible and return garbage search results. | **Model-Versioned Vector Tables & Auto-Reindexing Script**. Vectors are tagged with `embedding_model_id`. System detects mismatches and triggers background re-embedding. |
| 18 | **Reranker model changes**. | Score calibration shifts. | **Standardized Normalized Scoring [0, 1]**. Downstream logic uses rank order rather than raw uncalibrated logits. |
| 19 | **Local SLM model changes (e.g. Qwen to Llama-3)**. | Prompt format or tool-calling grammar breaks. | **Prompt Adapter Layer & Jinja2 Model-Specific Templates**. Decoupled prompt formatting based on model registry metadata. |
| 20 | **Inference engine changes (e.g. Ollama to llama.cpp)**. | API request format differences break business services. | **`InferenceEngine` Protocol Abstraction**. Gateway interacts only with unified internal Python protocol. |
| 21 | **Local model crashes / OOM during inference**. | Application crashes or hangs indefinitely. | **Subprocess Process Isolation & Health Watchdog**. Inference runs in an isolated worker process; API catches timeout/crash and returns standard `AI_UNAVAILABLE` fallback without crashing the core app. |
| 22 | **Tool execution fails / throws exception**. | Agentic workflow halts mid-stream. | **Graceful Tool Error Capture**. Tool errors are formatted as structured JSON error responses fed back into context for graceful recovery or human escalation. |
| 23 | **Tool returns malformed data**. | Downstream services crash. | **Pydantic v2 Tool Output Validation**. All tool returns are validated against strict output schemas before ingestion by the AI gateway. |
| 24 | **External / MCP server becomes unavailable**. | System blocks waiting for response. | **Circuit Breaker & Non-Blocking Fallback**. MCP is purely optional/supplementary; all core business tools are internal Python services that never depend on external MCP daemons. |
| 25 | **Agent enters a repetitive tool loop**. | High latency, wasted compute, frozen UI. | **Loop Prevention Guard (`max_iterations = 4`)**. State tracker detects duplicate tool calls and forces immediate loop termination with fallback to current best evidence. |
| 26 | **GPU VRAM exhausted**. | CUDA Out-of-Memory error. | **Dynamic Offload & CPU Fallback**. `LlamaCppEngine` detects available VRAM at startup and sets `n_gpu_layers` dynamically, overflowing to system RAM if necessary. |
| 27 | **PostgreSQL database becomes unavailable**. | Total application outage. | **Connection Pooling & Health Check Readiness Probes**. Immediate 503 response with auto-reconnect retry logic and cached static frontend fallbacks. |
| 28 | **Excel upload is malformed / corrupted**. | Ingestion crashes backend. | **Sandboxed Streaming Parser (`openpyxl` / `calamine`) with Strict Schema Validation**. Pre-validates magic bytes, sheet names, and headers before transactional processing. |
| 29 | **Excel units are wrong / inconsistent** (e.g. MWh instead of kWh, Lakhs instead of ₹). | Financial and KPI calculations skewed by $1,000 \times$. | **Unit Normalization Guard & Outlier Bounds Check**. Ingestion detects expected magnitude bounds (e.g. electricity ₹/veh between ₹500 and ₹5,000); flags anomalies for user confirmation before commit. |
| 30 | **Handwriting / scanned OCR is ambiguous**. | Inaccurate text fed to AI. | **Confidence Scoring on OCR Chunks**. Any OCR segment with character confidence < 80% is tagged `UNCERTAIN_TEXT` and presented alongside the original image snippet for human verification. |
| 31 | **Duplicate source records exist in upload**. | Double counting in OPEX or Ideathon count. | **Deduplication Hash on Ingestion**. Hash computed on `(plant_id, period, metric)` or `(source_id, raw_text)`. Duplicates are skipped with an audit notification. |
| 32 | **Enterprise sources disagree** (e.g. SAP says 100k units, Plant MES says 102k units). | Calculation discrepancy in ₹/vehicle KPIs. | **Source Priority Rules & Discrepancy Logging**. Master source priority hierarchy configured (ERP > MES > Manual Sheet) with discrepancy logged in the audit trail. |

## 3. Red-Team Findings & Plan V1 Attack Matrix

|---|---|---|---|---|---|---|---|---|---|---|
| **RT-01** | **AI / RAG** | V1 relies solely on vector similarity for Phase 5 before adding exact matching in Phase 6. | Vector search misses exact 10-digit part numbers, leading to false negatives during early testing. | **CRITICAL** | High | High | Automated tests for alphanumeric part search. | Combine exact trigram search and vector indexing into a single unified hybrid retrieval phase. | Merge Phase 5 and Phase 6 into Unified Hybrid Retrieval. | `PHASE-05` (Revised) |
| **RT-02** | **Runtime** | V1 places full Local AI Runtime in Phase 14 (late in sequence), risking late-stage integration surprises. | If `LlamaCppEngine` has memory leaks or C++ binding issues on host OS, it threatens POC delivery at the finish line. | **HIGH** | Medium | High | Continuous load testing of local inference engine. | Implement Track B runtime in parallel from Day 1; integrate and benchmark `LlamaCppEngine` early alongside business engines. | Promote Runtime Foundation to start in parallel with Phase 1. | `TRACK-B / PHASE-00+` |
| **RT-03** | **Data / OPEX** | Ingestion pipeline in V1 did not explicitly enforce canonical unit boundary checks on currency/energy. | Uploading figures in 'Lakhs' instead of 'Rupees' causes 100,000x calculation errors in OPEX benchmarking. | **HIGH** | High | High | Value range assertion tests in ingestion suite. | Add deterministic unit conversion engine with statistical magnitude sanity checks before database commit. | Expand Ingestion validation rules in Phase 2. | `PHASE-02` |
| **RT-04** | **Ideathon** | V1 allowed ideas with missing BOM data to stall in the pipeline. | In real enterprises, 40%+ of raw submissions lack initial part costs; pipeline must not stall. | **MEDIUM** | High | Medium | Ingestion of incomplete idea records. | Create explicit `UNQUANTIFIED_OPPORTUNITY` state that continues technical screening while queuing cost investigation. | Update Ideathon State Machine. | `PHASE-04` |
| **RT-05** | **Security** | V1 deferred air-gap egress validation to the final phase (Phase 16). | External network calls could inadvertently be introduced by third-party libraries during development. | **HIGH** | Medium | High | Automated egress packet sniffing in CI/CD. | Enforce container-level network isolation (`internal: true`) and zero-telemetry flags from Phase 0 onwards. | Move network egress constraints to Phase 0. | `PHASE-00` |
